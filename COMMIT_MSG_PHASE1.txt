## Why This Change

### Problem
The preview/queue system has fundamental architectural issues:
1. Every action type needs preview simulation logic
2. Selection dialogs check current state instead of preview
3. Continuous discovery of preview-related bugs
4. High maintenance burden for new actions
5. Not authentic to board game experience

### Solution
Phase 1 establishes the foundation for immediate execution:
- Actions execute instantly (no preview needed)
- AP deducted immediately (no queue)
- Single-level undo for mistakes
- State snapshots for reliable restoration
- Clear on phase advance (no cross-phase undo)

## Technical Details

### ActionHistory Design
```python
# Before (queue/preview):
queue.add_action(action)  # Preview state
queue.commit_all()        # Execute all

# After (immediate):
action.execute()          # Immediate
history.record_action()   # For undo
```

### State Snapshot Strategy
- Captures: position, facing, depth, torpedoes, damage states
- Uses deep copy for independent restoration
- Omits: unchanging data (crew status, etc.)
- Fast: <1ms for snapshot creation

### Integration Points
- TurnManager.remaining_ap: Current AP (not max)
- TurnManager.action_history: Reference to ActionHistory
- GameState.action_history: Owned instance
- Phase transitions clear history automatically
